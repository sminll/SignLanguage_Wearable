# 이번 주 수집·학습 계획

2026-11-03 사용자가 팀 톡방에 공유한 계획을 기준으로 한다. 후속 명시적 변경 전까지 새 실험에 적용한다.

## 측정 조건

- 대상 수어: **삼키다 / 상처 / 교통사고**. 이번 주에는 같은 세 수어를 여러 사람에게 받는다.
- 장치는 장갑형이 아니라 **FSR이 붙은 밴드·스트랩형**이다.
- 착용 위치: **손목에서 팔꿈치 방향으로 전체 길이의 2/5 지점**.
- 센서 방향은 팀에서 공유한 사진을 따른다. 해당 사진은 아직 이 저장소에서 확인한 자료가 아니므로 방향·채널 순서를 임의로 만들어 기록하지 않는다.
- 수어는 팀의 기준 영상에 따라 **손내림·손올림까지 포함해 5초 동작, 3초 휴식**한다. 기존 20회 반복 기준을 유지한다.
- 조임·압박 기준과 센서 방향·위치 및 측정 자세는 가능하면 함께 기록한다. 정확한 압박 수치가 정해지지 않았다면 수치 기준을 임의로 확정하지 않는다.

## 데이터 구분

| 데이터 | 역할 | 확인 사항 |
| --- | --- | --- |
| 오늘 앱 subject-1(성윤님)·subject-2(영훈님) | 위치 통일 전 **초기 비교용**, 원본·기존 실험 모델 보존 | 새 기준 모델에 자동 혼합하지 않음 |
| 상민님 교통사고 데이터 | 새 기준 학습 데이터에 포함할 계획 | 앱 subject-5가 해당 측정인지, 2/5 위치와 방향을 적용했는지 확인 후 연결 |
| 내일 이후 다른 참가자 | 위치·방향·동작 조건을 맞춘 새 기준 데이터 | 사람별 ID·실제 측정 조건 기록 |

사용자가 확인한 앱 subject-1/2 이름은 이번 앱 데이터의 대응이다. 이를 과거 모든 ESP32/MATLAB 세션의 동일인 확인으로 확대하지 않는다. 상민님 데이터는 교통사고만 있으므로 현재 세 수어가 모두 갖춰진 참가자로 취급하지 않는다.

## 학습·평가 순서

1. 품질검사 후 위치 통일 데이터로 새 기준 모델을 만든다. 초기 subject-1/2 모델과 구분한다.
2. 학습에 넣지 않은 참가자를 **먼저 정해 두고**, 그 참가자의 전체 회차를 평가용으로 분리한다. 학습과 평가에 같은 사람·같은 회차의 샘플을 섞지 않는다.
3. 모델 설정을 고정한 상태로 평가하고 결과를 기록한다. 그 후 해당 참가자를 학습에 추가할 수 있다. 추가 후에는 그 사람을 독립 평가 대상으로 다시 보고하지 않는다.
4. 초기 subject-1/2를 추가한 모델과 추가하지 않은 모델을 **동일한 별도 평가 참가자**로 비교한다. 같은 평가 결과를 반복 확인하며 튜닝했다면 최종 검증용 사람을 따로 둔다.
5. 수어 동작이 정상이고 수집에 명확한 결함이 없다면 오인식만으로 버리지 않는다. 센서 고장·라벨 오류·동작 실패·심한 누락처럼 확인된 문제를 회차별로 처리한다.

## Edge Impulse 실험

사용자는 Edge Impulse 프로젝트 `https://studio.edgeimpulse.com/studio/1155481` 사용을 검토 중이다. 현재 접근·설정·데이터 업로드를 수행한 상태가 아니다.

KNN을 비교 기준으로 유지하고, 같은 선별 회차와 같은 사람별 학습/평가 구분으로 Edge Impulse 모델을 시험한다. 도구를 바꾼 효과와 데이터/평가 분할을 바꾼 효과가 섞이지 않게 한다. 새 기준 데이터가 확보되면 양손 시간 기준을 확인하고, 호환되는 시간열·센서열 형태로 회차별 변환한다. 보정/시험 기록을 수어 라벨로 섞지 않는다.

## 현재 실행 상태

이번 계획을 기록했으며 새 학습은 실행하지 않았다. 1+2 모델의 subject-5 교통사고 평가 12/20(60%)는 **초기 위치 조건의 탐색 실험 이력**으로 유지한다. 이를 새 착용 기준의 검증 성능으로 해석하지 않는다. 원본·기존 모델은 삭제하지 않는다.
