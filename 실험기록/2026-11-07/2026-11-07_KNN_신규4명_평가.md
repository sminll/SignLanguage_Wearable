# 11월 7일 신규 4명: KNN 설정 선택·외부 평가·통합 후보

분석: **2026-11-08**. 고정 Git 커밋 `8b21c3a145f08969dc17f739c0a96f3fcedf5f21`.

## 결론과 현재 후보

**기존 데이터에서만 설정을 선택한 IMU 전용 KNN은 신규 4명·240회차에서 148/240(61.67%)였다. 기존 전체 센서 모델은 같은 데이터에서 137/240(57.08%)였다.** 정답 +11회(+4.58%p)지만 사람별 편차가 크므로 최종 안정화 완료로 판단하지 않는다.

선택된 설정은 **양손 IMU만 / StandardScaler / KNN k=3 / 균등 투표 / 맨해튼 거리(p=1)**다. 평가 결과를 본 뒤 설정을 바꾸지 않았다.

평가를 저장한 다음 기존 초기 제외 319회차와 신규 240회차를 합쳐 **559회차·10명으로 새 후보를 학습**했다. 초기 subject1·2의 120회차는 계속 제외했다. 새 후보는 모든 참가자를 학습했으므로 다시 새 사람/새 세션으로 확인해야 한다. 자동 배포하지 않았고 기존 모델은 보존했다.

## 학습·설정 선택·평가 분리

1. **개발 자료:** 기존 초기 제외 319회차, subject1 재측정·5·6·8·9·10. 초기 두 사람 120개 파일은 경로/해시로 제외했다.
2. **외부 평가 자료:** 11/7 subject2·3·4·7의 240회차. 설정 선택에 넣지 않았다. 개발/평가의 사람 번호·파일은 서로 겹치지 않는다.
3. 회차별 평균·표준편차(ddof=0)·최소·최대를 계산한다. 전체 센서는 96특징, 왼손 FSR 제외 72, 양손 IMU 전용 48이다. 5초 동작 1회가 샘플 하나다. 정밀 양손 시각 정렬을 검증했다는 뜻은 아니다.
4. 개발 자료에서 센서 구성 3종 × scaler 2종(Standard/Robust) × k 5종(1/3/5/7/9) × 투표 2종(균등/거리) × 거리 2종(맨해튼/유클리드) = **120설정**을 비교했다.
5. 설정 선택은 세 수어가 있는 개발 참가자 5명을 각각 뺀 평가의 **사람별 균형 정답률 평균**으로 했다. subject5는 교통사고만 있으므로 선택 점수를 과도하게 높이지 않도록 평가 평균에서는 제외하되, 다른 사람 평가의 학습에는 포함했다. 각 fold의 전처리는 학습 사람에서만 계산했다.
6. 120설정 중 선택한 내부 점수는 77.33%였으나 이는 **설정 선택 점수**이지 최종 외부 정확도가 아니다. `locked_selection.json`을 먼저 저장한 뒤 신규 4명 예측을 생성했다. 새 평가 점수로 다른 설정을 다시 고르지 않았다.
7. 기존 319회차로 학습한 전체 센서 후보는 재학습하지 않고 그대로 신규 240회차를 평가해 비교했다. 모델 파일 해시가 평가 전후 동일함을 확인했다.
