## 확인된 정상 항목

- 모든 파일에 양손, FSR 6개, IMU 6축, 측정자·세션·회차 식별 정보가 있다. 파일마다 하나의 수어·회차로 구성된다.
- 손별 회차당 49~52개 샘플, 장치 시간 기준 길이 약 4.826~5.144초다.
- 회차 내 시간 간격은 중앙값 약 100ms(약 10Hz), 최대 104ms다. 큰 공백·시간 역전은 없다.
- 회차 내 손별 순번 누락·중복·역전이 없다. 파일 간 `(subject_id, session_id, hand, sample_seq)` 중복도 없다. 회차 사이 휴식 동안의 순번 공백은 이 판정의 누락 대상으로 보지 않는다.
- FSR·IMU 결측/무한값·음수 FSR이 없고 `imu_ok=1`이다. 회차 전체에서 완전히 고정된 센서 채널은 없다. 순번 정상과 imu_ok 표시는 실제 동작의 정확성 또는 BLE 패킷 무손실의 보증이 아니다.

## 확인이 필요한 사항

### 1. 오른손 FSR5의 작은 반응

| 수어 | FSR5가 0인 샘플 비율 | 최대값 |
| --- | ---: | ---: |
| 교통사고 | 84.7% | 112 |
| 삼키다 | 83.1% | 79 |
| 상처 | 81.9% | 115 |

다른 오른손 압력 채널은 수백~수천까지 반응한다. 해당 위치에 실제 압력이 걸리지 않는 정상 동작일 수도 있으므로 고장으로 단정하거나 낮은 값만으로 회차를 삭제하지 않는다. 측정 전 해당 FSR을 직접 눌렀을 때 반응하는지, 채널이 어느 부위인지 확인하는 것이 좋다.

### 2. 왼손 압력 채널의 매우 유사한 반응

교통사고의 왼손 FSR 6채널 간 상관계수는 약 0.982~0.986, 상처는 0.969~0.974다(각 수어의 전체 샘플 기준). 공동 접촉으로 함께 눌렸을 수 있지만, 배선/공통 신호/채널 매핑도 확인할 항목이다. 상관이 높다는 이유만으로 제외하지 않는다. 개별 센서를 하나씩 눌렀을 때 각각 구분되어 반응하는지 확인한다. 삼키다의 왼손 상관 범위는 약 0.655~0.823이다.

### 3. 삼키다의 작은 왼손 움직임

왼손 가속도 구간 내 표준편차는 축별 평균 약 0.004~0.007, 자이로는 약 0.66~1.06이다. 오른손은 더 많이 움직인다. 오른손만 사용하는 수어라면 정상일 수 있다. CSV 양손 수집과 수어 자체의 양손 동작 여부는 별개이므로, 수어 유형을 확인하기 전 잘못된 동작으로 판정하지 않는다.

### 4. 보정·시간·측정자 정보

- 전 파일에 `calibration_version=UNREGISTERED`, `calibration_verified=false`가 있다. 보정이 검증됐다는 기록이 없다는 뜻이며, 신호 자체가 반드시 불량이라는 뜻은 아니다. 앱의 해당 필드 생성 규칙을 확인해야 한다.
- `time`에는 UTC 시각이 있고 `time_ms`에는 장치 시간이 있다. 다만 `time`이 BLE 수신 시각인지 측정 시각인지, 앱이 양손을 어떤 공통 시계로 기록하는지 아직 확인되지 않았다. 기존 서버 v3 전용 필드가 없다는 이유만으로 앱 시간이 쓸모없다고 보지 않는다. 정확한 정렬 가능 여부는 앱 구현 확인 전 미검증이다.
- 한 회차의 양손을 함께 저장한 구조는 갖췄다. 정밀 시계 정렬 없이 손별 회차 통계를 합치는 분석은 가능하지만 정렬 검증 완료로 표현하지 않는다.
- 모든 파일은 `subject-1`, 동일 `session_id`를 사용한다. 여러 수어가 같은 앱 세션 아래에 있으므로 전처리는 세션에 라벨이 하나뿐이라고 가정하면 안 된다. 회차 `trial_id`는 파일별로 구분된다.
- 앱의 `subject-1`이 기존 MATLAB의 `subject1`과 같은 사람인지는 별도 확인이 필요하다. 자동으로 이름을 매핑하지 않는다.

## 다음 단계

1. 측정자에게 각 수어의 왼손만/오른손만/양손 동작 여부를 확인한다.
2. 오른손 FSR5의 직접 누름 반응과 왼손 개별 FSR 채널 구분을 확인한다.
3. 앱 담당자에게 보정 필드 의미와 시각 생성 방식, subject ID 대응을 확인한다.
4. 확인 후 원본과 별개의 사용 회차 목록으로 학습 후보를 정한다. 현재 60개 모두 보존한다. 사람 1명·앱 세션 1개이므로 다른 사람/세션으로의 일반화 정확도는 아직 평가할 수 없다.
