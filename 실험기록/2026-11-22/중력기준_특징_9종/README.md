# 중력 기준 좌표 특징 수어 분류기와 평가 기록

2026-11-24 시연 준비 지시서에 따라 11월 23일 실행했습니다. 기록 폴더 날짜 11/22는 요청된 경로를 유지한 것입니다. 코드 기준 main은 84d423ac4f47243420b3ed74a2d8b39a22e9eea7, 최신 training-data 및 기준 데이터는 모두 0f4b1eef59723ea42ebebe320ed6094db289bb4d였습니다. 시작 전에 git fetch origin을 수행했습니다. 과거 6종 비교는 4d4d24a4d672c78d934bf120a59a193c2340637e를 사용했습니다. 원본 CSV·기존 코드·문서·모델과 앱·MATLAB·펌웨어·tools/·docs/는 수정하지 않았고, 운영 모델을 교체하거나 배포하지 않았습니다.

루트의 sign_gravity_model.py 한 파일에 evaluate, train, predict CLI를 추가했습니다. 비교용 evaluate --axis-baseline 및 실제 회전 검증용 selfcheck도 같은 파일에 있습니다. 외부 의존성은 NumPy, pandas, scikit-learn, joblib뿐입니다. 나머지 추가 파일은 이 기록 폴더의 실험 결과입니다. 실행 환경의 scikit-learn 1.9.1, NumPy 2.5.4는 지시서와 일치하며, Python·pandas·joblib 및 검증 환경의 SciPy 버전은 JSON에 기록했습니다. estimators의 random_state는 20261122, 지원되는 n_jobs는 1입니다. 검증 실행에서 BLAS 스레드도 1로 제한했습니다. 이 scikit-learn 버전의 LogisticRegression은 n_jobs=1이 효과가 없다는 FutureWarning을 내지만 오류는 아니며, 값을 바꿔 결과를 조정하지 않았습니다.

데이터는 고정한 커밋의 sensor-data/training을 git archive로 메모리 tar에 읽었습니다. CSV 하나를 회차 하나로 취급하며, 다른 파일의 좌우 손은 연결하지 않았습니다. 같은 (hand, sample_seq)의 중복 행은 첫 행만 남깁니다. XIAO·REAL·training과 좌우 손 각각의 샘플 수·시간 길이·간격·IMU 유효성·센서 유한값 기준을 검사했습니다. 손 하나만 있는 기록은 이번 실험에서 제외했습니다. 현재 data/training_exclusions.json의 files 목록만 적용하고 history는 학습 제외 목록으로 사용하지 않았습니다. 별칭과 숫자 Subject 정규화는 지시서의 규칙을 따랐습니다. 제외 사유와 개수는 각 summary.json에 남겼습니다.

특징은 손마다 자이로 크기가 낮은 30% 구간의 가속도 평균으로 중력 기준을 추정하고, 그 방향이 +z가 되도록 가속도·자이로를 함께 회전해 계산했습니다. 중력 방향 성분과 수평 크기, 기준 가속도 대비 변화 크기, 자이로 크기의 6채널을 사용하며 FSR은 특징에 넣지 않았습니다. 전체·3분할 통계와 움직임 구간의 같은 통계, 움직임 비율, 움직임 구간의 12점 재표본화를 합쳐 손당 266개·양손 532개입니다. 통계 배열은 평균 열 벡터, 모집단 표준편차 열 벡터, 최솟값 열 벡터, 최댓값 열 벡터 순서입니다. 움직임의 자동 시작·끝 검출이나 휴식 분류기를 배포한 작업은 아닙니다. 중력 기준을 정의할 수 없는 영벡터는 임의 축을 가정하지 않고 사유를 기록해 제외합니다.

평가는 사람을 그룹으로 하는 기본 순서의 바깥 GroupKFold(5)입니다. 각 바깥 학습 자료 안에서만 GroupKFold(3)로 7개 후보의 예측을 모아 balanced_accuracy를 계산해 설정을 고릅니다. 후보 순서는 lr_c0.01, lr_c0.05, lr_c0.2, extratrees, svm_c1, svm_c10, lr0.05+extratrees이며 정확히 같은 점수일 때 앞 후보를 고릅니다. StandardScaler와 분류기 적합은 각 학습 묶음 안에서만 수행했고, 시험 사람의 회차를 설정 선택에 사용하지 않았습니다. 9종은 CLI를 직접 실행했고, 여러 비교는 같은 모듈 함수를 호출해 고정된 특징을 재사용했습니다. 기본 세션 정규화는 사용하지 않았습니다.

9종은 교통사고·삼키다·상처·괜찮다·마시다·무엇·싫다·아니다·화장실이며 10명·2,009회 중 1,048회 정답, 정확도 52.17%, 균형 정확도 49.42%입니다. 우연 수준은 균등한 9개 선택 기준 11.11%이며 실제 클래스 개수 차이를 반영한 다수 클래스 기준도 summary.json에 별도로 있습니다. 지시서의 기준 1,049/2,009(52.22%)보다 정답이 1회 적고 정확도는 약 0.05%p 낮았습니다. 선택된 바깥 설정으로 다시 학습·예측해 2,009개 예측이 전부 같은 것도 확인했습니다(verification/nine_sign_selected_prediction_replay.json). 이 차이를 없애려고 코드·후보·난수·특징 순서를 사후 변경하지 않았습니다.

3종 교통사고·삼키다·상처는 730/779회, 93.71%로 기준과 같습니다. 6종 괜찮다·마시다·무엇·싫다·아니다·화장실은 591/1,230회, 48.05%로 기준과 같습니다. 과거 커밋의 6종은 508/1,170회, 43.42%로 기준과 같았고, 회차 경로와 원본 SHA256이 기존 실험기록/2026-11-18/IMU크기_동작구간_비교/cohort_manifest.csv의 1,170개와 모두 같았습니다. 최신 1,230회와 과거 1,170회는 자료 범위가 다르므로 두 정확도 차이를 전처리만의 개선으로 해석하지 않습니다.

4종 교통사고·삼키다·상처·아니다는 지시서의 별칭 처리까지 적용하면 1,005회가 됩니다. ‘아니다 (아니, 부인(하다))’ 20개가 ‘아니다’로 포함되기 때문입니다. 이 기본 동작의 결과는 880/1,005회, 87.56%입니다. 별칭 요구를 제거하거나 기본 코드를 숫자에 맞춰 변경하지 않았습니다. 대신 그 20개 경로를 --exclude-paths로 명시적으로 제외한 별도 참고 실행에서 873/985회, 88.63%를 재현했습니다. B의 시연 브랜치는 첫 데이터 행 라벨의 정확한 일치만 사용하므로 이 985개 범위와 맞습니다. 제외 경로는 verification/four_sign_alias_exclusions.txt, 결과는 comparisons/gravity_4_literal_labels에 있습니다. 두 4종 결과를 섞어 보고하지 않습니다.

비교용으로 같은 사람 분리·설정 선택 절차에서 원래 축의 acc·gyr 6채널 phased 특징만 사용하면 9종 826/2,009회(41.11%), 3종 611/779회(78.43%)로 지시서와 같습니다. 중력 기준 특징의 이번 실제 9종 결과는 같은 회차에서 222회·11.05%p, 3종은 119회·15.28%p 높았습니다. 이는 두 특징 묶음 전체를 비교한 결과이며, 중력 회전 하나만의 독립 효과를 분리한 실험은 아닙니다. 9종의 정답 1회 차이는 동일 데이터 커밋·회차 수·지정 NumPy/scikit-learn 버전을 확인해도 남습니다. 참조 구현 전체와 pandas·SciPy·BLAS 등의 기준 실행 환경 정보가 없어 원인을 단정할 수 없습니다. 나머지 라이브러리·플랫폼과 부동소수 연산/동등한 회전행렬 구현의 수치 차이를 원인 후보로 기록하며, 기준 숫자로 보정하지 않았습니다.

9종에서 한 손 수어인 괜찮다는 39/214회(18.22%), 싫다는 41/192회(21.35%), 화장실은 42/192회(21.88%)로 낮았습니다. 교통사고는 238/280회(85.00%), 상처는 193/239회(80.75%)였습니다. 자세·착용·동작과 특징 표현이 어떤 영향을 주었는지는 이 결과만으로 하나의 원인으로 확정하지 않습니다. 사람별 결과와 혼동행렬을 함께 확인해야 하며, 낮은 정답률의 회차를 사후 제거하지 않았습니다.

실제 9종의 양손 기록 4,018개에 각각 임의의 3차원 회전을 동일하게 acc·gyr에 적용해 손 특징을 다시 계산했습니다. 모두 rtol=1e-8, atol=1e-8 범위에서 같았으며 최대 절대 차이는 3.979039320256561e-13입니다. +z의 단위행렬과 -z의 diag(1,-1,-1) 처리도 검사했습니다. 검증 숫자는 verification/rotation/rotation_invariance.json에 있습니다. 이 회전 불변성은 실제 센서의 위치 이동이나 조임 차이·새로운 사용자의 동작까지 보정됨을 뜻하지 않습니다.

train은 전체 4종 1,005회에서 설정을 선택해 별도의 lr_c0.05 후보를 임시 작업 폴더에 저장했습니다. 모델·정보·feature_version=1·training_manifest와 532차원을 확인했습니다. 학습 CSV 하나를 predict에 넣어 정상 출력되고 보정 CSV 하나는 not_training 사유로 건너뛰는 것을 실제 실행했습니다. 이 예측은 저장/입력 경로 확인용이며 학습 회차를 다시 맞힌 정확도로 보고하지 않았습니다. CSV의 정답 라벨을 바꿔도 예측이 같음을 확인했습니다. 기존 모델을 덮어쓰지 않았고 후보 model.joblib도 이 PR에 넣거나 앱에 배포하지 않았습니다.

총 24개 QC·CLI 검사를 통과했습니다. 출력 폴더가 이미 있을 때는 코드 2로 중단하며 기존 sentinel 파일이 보존됐습니다. --data-dir의 원본 바이트·특징 일치, 중복 제거, 샘플·시간·간격·유효성·유한값 검사, 현재 제외 목록과 history 구분, 숫자 Subject 정규화, 5명 미만 평가 중단도 확인했습니다. 원래 축 비교와 중력 특징 결과의 정확도·균형 정확도·수어별/사람별 합계·혼동행렬·바깥 사람 분리·내부 최고 점수 선택을 결과 파일로 재검산했습니다. CSV·JSON 결과는 모두 UTF-8 BOM으로 저장했습니다. 검증용 가상 입력은 실제 평가 숫자에 포함하지 않았습니다.

--session-norm은 실제 9종 자료에 실행했으나 세션별 수어 구성이 달라 이유를 출력하고 중단했습니다. 이 경우 출력 폴더나 정규화 정확도를 만들지 않았습니다. 구성이 같은 자료에서 사용할 때도 세션 전체, 시험 쪽에서는 시험 세션 전체 특징을 정규화에 이용하는 평가 전용·비실시간 참고 옵션입니다. 학습 모델이나 predict에 이 변환을 적용하지 않습니다.

결과 파일은 predictions.csv, selected_configs.csv, per_sign.csv, per_person.csv, confusion.csv, summary.json이며 비교 결과는 comparisons/ 아래에 별도로 있습니다. 결과 검산과 회차·해시 일치는 verification/result_integrity.json, 실행·QC 검사는 verification/cli_and_qc_checks.json, 실제 세션 정규화 거부는 verification/session_norm_refusal.json을 참고합니다. summary.json의 commit과 verification/result_integrity.json의 source_sha256으로 원본 데이터와 실행 코드를 구분합니다.

재현 예시는 `python sign_gravity_model.py evaluate --ref 0f4b1ee --signs 9 --out 새폴더`, `python sign_gravity_model.py evaluate --ref 0f4b1ee --signs 3 --out 다른새폴더`, `python sign_gravity_model.py evaluate --ref 0f4b1ee --signs 9 --axis-baseline --out 축비교새폴더`입니다. 정확한 라벨의 4종 참고 결과는 `--signs "교통사고,삼키다,상처,아니다" --exclude-paths 실험기록/2026-11-22/중력기준_특징_9종/verification/four_sign_alias_exclusions.txt`를 지정합니다. 회전 검사는 `python sign_gravity_model.py selfcheck --signs 9 --ref 0f4b1ee --out 회전검사새폴더`, 별도 후보 학습은 `python sign_gravity_model.py train --signs 3 --out 새모델폴더`, 입력 확인은 `python sign_gravity_model.py predict --model 새모델폴더/model.joblib 측정.csv 보정.csv`로 실행합니다. 실제 사용하는 신뢰할 수 있는 joblib만 읽어야 합니다.
