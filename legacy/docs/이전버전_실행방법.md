# MATLAB FSR 6채널 + IMU 실시간 그래프

1. Arduino IDE의 시리얼 모니터와 시리얼 플로터를 닫습니다.
2. MATLAB에서 이 폴더의 `fsr_live_monitor.m`을 열고 Run을 누릅니다.
3. 자동 포트 선택이 안 되면 MATLAB Command Window에서 다음처럼 실행합니다.

```matlab
cd('/Users/jkh/Downloads/ESP32_센서_시리얼_20261027/MATLAB_FSR6')
fsr_live_monitor('/dev/cu.usbserial-1440')
```

현재 포트 목록은 `serialportlist("available")`로 확인합니다. USB를 옮기면 포트 이름이 바뀔 수 있습니다.
macOS에서 같은 장치의 `/dev/cu.*`와 `/dev/tty.*`가 함께 보이면 해당 `/dev/cu.*`를 선택합니다. 서로 다른 USB 장치가 여러 개면 포트를 직접 지정합니다.

하나의 창 위쪽 전체 폭에 FSR 6개 파형을 서로 다른 색상으로 겹쳐 표시합니다. 범례에는 GPIO25, GPIO26, GPIO34, GPIO33, GPIO32, GPIO35와 각 GPIO의 최신 ADC 값을 표시합니다. FSR 세로축 기본 범위는 0~500입니다. 창 위쪽 `Y max (ADC)`에서 50·100·200·500·1000·4095 중 표시 상한을 바꾸면 FSR 좌표축에만 즉시 적용됩니다. 상한을 넘는 데이터는 그래프 영역 밖으로 나가지만 범례의 현재값은 실제 수신값을 표시합니다. ADC 수신값은 원시값 0~4095를 그대로 사용하며 정규화·변환하거나 잘라내지 않습니다.

아래 왼쪽에는 IMU 가속도 AX·AY·AZ(g), 아래 오른쪽에는 각속도 GX·GY·GZ(deg/s)를 각각 표시합니다. IMU 세로축 범위는 자동 조정되며, IMU 칩 온도(℃)는 가속도 그래프 제목에 표시합니다. 세 그래프 모두 최근 20초를 표시하고, ESP32를 재시작해 타임스탬프가 줄어들면 그래프 시간과 궤적을 초기화합니다.

코드를 수정한 뒤에는 기존 그래프 창을 닫고 `clear fsr_live_monitor`를 실행한 다음 다시 시작합니다.

ESP32가 보내는 `ms, FSR 6개, IMU 7개`의 14열 CSV를 읽습니다. 부팅 메시지·불완전한 행은 건너뜁니다. IMU의 `nan`·`inf` 값은 `NaN`으로 처리해 해당 파형 구간을 비워 두며, FSR 수신값이 유효하면 FSR 6개는 계속 표시합니다. 새 데이터가 2초 이상 없으면 화면 위에 경과 시간을 표시합니다. 입력값을 평활화하거나 보정하지 않습니다.

종료하려면 그래프 창을 닫거나 Command Window에서 Ctrl+C를 누릅니다. 종료하면 시리얼 포트를 해제합니다. 그래프를 사용하는 동안 같은 포트를 Arduino IDE나 MCP에서 동시에 열지 않습니다.

MATLAB R2025b 기본 기능(`serialport`, `tiledlayout`, `animatedline`)을 사용합니다. 현재 그래프에는 KNN·힘 환산 기능을 포함하지 않았습니다. 동작 수집 데이터는 아래 설명대로 CSV 파일에 저장합니다.

## 동작 20회 수집 후 HTTP 전송

1. 위 방법대로 `fsr_live_monitor`를 실행합니다.
2. 창 상단의 `동작명`에 `가위`처럼 회차 숫자가 없는 동작 이름을 입력합니다.
3. 손 선택에서 `왼손 (L)` 또는 `오른손 (R)`을 선택합니다.
4. `20회 수집 시작`을 누릅니다. 프로그램 폴더의 `sensor_data/`에 이번 수집용 CSV 파일을 만들고, 첫 새 센서 프레임을 받은 시점부터 수집을 시작합니다.
5. 화면의 `수집` 구간에는 해당 동작을 5초 유지하고, `이완` 구간에는 3초 동안 손을 편하게 둡니다. 이를 20회 반복합니다. 마지막 3초 이완까지 포함해 약 160초이며, ESP32가 보낸 `millis()`를 기준으로 구간을 나눕니다.
6. 동작을 실패하면 `중지`를 누릅니다. 수집한 샘플은 메모리와 CSV 파일에 보관하며, 중지하거나 `20회 수집 완료`가 되어도 자동으로 전송하지 않습니다.
7. 실패한 회차는 `최근 회차 삭제`로 지웁니다. 해당 회차의 샘플 전체를 메모리와 CSV 파일에서 삭제하고 그 회차의 5초 수집 시작점으로 돌아갑니다. 앞선 회차의 데이터는 보존합니다. `계속 수집`을 누르면 해당 회차를 다시 수집합니다.
8. 삭제 없이 `계속 수집`을 누르면 멈춘 지점부터 이어집니다. 중지한 동안의 시간은 5초 수집·3초 이완 계산에서 제외합니다.
9. 수집을 중지했거나 20회 수집이 끝난 뒤 데이터를 확인하고 `전송`을 눌러 HTTP 전송을 시작합니다. HTTP 요청 전에 이번 수집의 전체 보관 샘플을 CSV 파일에 저장합니다. 전송 중에는 수집·삭제 버튼을 사용할 수 없으며, 전송이 끝날 때까지 창을 열어 둡니다.

전송을 시도하기 전에 처음부터 다시 수집하려면 `전체 삭제`를 누릅니다. 메모리의 보관 샘플을 모두 지우고 이번 CSV 파일에는 열 이름만 남깁니다. 전송을 한 번이라도 시도하면 이 버튼은 `새 수집`으로 바뀝니다. `새 수집`은 메모리만 정리하고 기존 CSV 파일은 보존합니다. 동작명과 손을 선택하고 다시 시작하면 새 CSV 파일을 만듭니다. 이미 POST한 데이터를 서버에서 삭제하는 기능은 없습니다.

5초 수집 구간의 샘플만 보관하며, 3초 이완 구간의 샘플은 보관·전송하지 않습니다. 실시간 그래프는 수집 여부와 관계없이 계속 갱신됩니다. 수집 중 ESP32가 재시작되어 타임스탬프가 줄어들면 수집을 중단합니다. 중지하거나 창을 닫아도 이미 저장한 CSV 파일은 남습니다.

새 20회 수집마다 `sensor_data/가위_L_yyyyMMdd_HHmmss_SSS.csv`처럼 동작명·손·시각을 포함한 파일을 만듭니다. 같은 이름이 있으면 숫자 접미사를 붙여 기존 파일을 보존합니다. 화면 상단 둘째 줄 오른쪽에 CSV 파일명을 표시하며, 마우스를 올리면 전체 경로를 확인할 수 있습니다. 수집한 프레임은 매번 CSV에 추가하고 파일을 닫으므로 메모리에만 남지 않습니다. CSV 생성·저장에 실패하면 수집 또는 전송 시작을 중단하고 메시지를 표시하며, 이미 메모리에 보관한 샘플은 유지합니다.

`전송`을 누르면 보관 샘플을 `http://100.122.78.26:5000/sensor`에 17개 필드의 JSON 객체로 한 개씩 POST합니다. 요청 한 번에 샘플 한 개를 보내며, 백그라운드에서 수신 순서대로 전송합니다. MATLAB R2025b의 `backgroundPool`을 사용하므로 Parallel Computing Toolbox를 별도로 설치할 필요는 없습니다.

CSV 파일의 17개 열은 아래 JSON 필드와 이름·순서가 같습니다. 파일은 UTF-8로 저장하며 원시값과 단위를 그대로 보존합니다. 전송용 대기 목록과 별도로 이번 수집 전체를 보관하므로 POST 성공·실패 후에도 CSV 데이터는 유지됩니다.

| JSON 필드 / CSV 열 | 값과 단위 |
|---|---|
| `source` | 동작명 + 회차. `가위`를 입력하면 `가위1`부터 `가위20`까지 사용 |
| `device_id` | 왼손은 `"L"`, 오른손은 `"R"` |
| `seq` | 수집 샘플마다 1씩 증가하는 정수. 같은 MATLAB 모니터 실행 중 새 20회 수집을 시작해도 초기화하지 않으며, 삭제한 샘플의 번호는 건너뛸 수 있음 |
| `time_ms` | ESP32 부팅 후 경과 밀리초. 5초는 `5000`이며, Unix 시각이나 초 단위가 아님 |
| `fsr1_raw`, `fsr2_raw`, `fsr3_raw`, `fsr4_raw`, `fsr5_raw`, `fsr6_raw` | 수신한 원시 ADC 값. 정규화·평활화·힘 환산 없음 |
| `ax_g`, `ay_g`, `az_g` | IMU 가속도, g 단위 |
| `gx_dps`, `gy_dps`, `gz_dps` | IMU 각속도, deg/s 단위 |
| `imu_ok` | IMU 6축 값이 모두 유효하면 숫자 `1`, 하나라도 유효하지 않으면 숫자 `0` |

IMU의 `nan`·`inf`는 CSV에 `NaN`으로 저장하고, 해당 JSON 필드에는 `null`로 보내며 `imu_ok`를 `0`으로 기록합니다. 누락된 IMU 값을 가짜 `0`으로 만들지 않습니다. IMU 칩 온도는 그래프에만 표시하며 CSV·POST에는 포함하지 않습니다.

학습 데이터를 만들 때 `가위1`~`가위20`은 회차를 구분하는 이름입니다. 같은 동작의 학습 클래스는 회차 숫자를 뺀 `가위`로 묶어야 합니다.

화면에는 전송 대기 샘플 수와 전송 상태를 표시합니다. CSV 파일은 전송 대기 목록과 별도로 이번 수집 전체를 보관합니다.

- `전송 확인`: HTTP 성공 응답을 받은 샘플 수입니다.
- `보관`: 아직 전송 대기 중인 샘플 수입니다.
- `전송 중`: 현재 백그라운드 전송 작업에 들어간 샘플 수입니다.
- `미확인`: 전송 오류 등으로 서버 저장 여부를 확인하지 못한 샘플 수입니다. 요청이 서버에 도착했지만 응답만 유실되었을 수도 있습니다.

HTTP 요청이 실패하면 전송을 중단하며 자동 재시도하지 않습니다. 아직 보내지 않은 샘플은 메모리에 보존하고, 오류가 난 요청의 서버 저장 여부는 `미확인`으로 표시합니다. 다시 전송하면 미확인 샘플이 서버에 중복 저장될 수 있습니다. 전송 중 창을 닫으면 전송을 취소하며, 진행 중 요청의 서버 저장 여부는 확인할 수 없습니다. 창을 닫으면 메모리는 사라지지만 CSV 파일에는 이번 수집 데이터가 남습니다.

HTTP 응답 대기시간은 요청별 10초입니다. 이는 서버에 연결할 수 있게 만드는 설정은 아니므로, 접속 자체가 되지 않으면 서버 실행 상태와 주소·네트워크도 확인해야 합니다.

## 검증 범위

이전 버전은 MATLAB R2025b의 코드 분석기로 모니터와 HTTP 관련 코드·테스트 7개 파일을 검사해 경고 없이 통과한 기록이 있습니다. CSV 저장을 추가한 이번 버전의 9개 파일은 MATLAB 코드 분석기(`mlint`)가 수분 동안 응답하지 않아 Ctrl+C로 중단했습니다(종료 코드 130). 이번 버전의 정적 검사 완료나 실제 실행 성공은 확인하지 못했습니다.

`test_sensor_http.m`은 JSON 구성·수집 구간 경계·전송 헬퍼 입력을, `test_sensor_collection_review.m`은 전송 없이 보관·중지·재개·삭제 동작을, `test_sensor_csv.m`은 CSV 저장·보존 동작을 검사하도록 작성했습니다. GUI 관련 테스트는 임시 폴더를 사용하므로 프로그램의 `sensor_data/`에 시험 데이터를 남기지 않습니다. 이 폴더에서 다음처럼 실행합니다.

```matlab
runtests({'test_sensor_http.m','test_sensor_collection_review.m','test_sensor_csv.m'})
```

이 작업 환경에서는 MATLAB 본체의 명령줄 실행이 출력 없이 종료 코드 1로 끝나 실제 장치 수신·그래프 실행·단위 테스트 실행을 검증하지 못했습니다. 대상 서버 연결도 현재 TCP 타임아웃이 발생해 실제 POST 성공과 서버 저장 여부는 확인하지 못했습니다.
