# 단일 보드 수집 후 서버 전송

전송 주소는 `http://100.92.15.45:5000/sensor`입니다. Mac에서 서버 PC가 Tailscale 장치 목록에 보여야 합니다. `/health` 응답만으로 센서가 저장된 것은 아닙니다.

1. 이 폴더를 MATLAB 경로에 등록하고 기존과 같이 `b`, `c`를 연결한 뒤 `subscribe(c,"notification")`를 실행합니다.
2. `xiao_ble_single_ui_test(c)`를 실행합니다. 기존 `xiao_ble_reconnect`도 같은 모니터를 엽니다.
3. **수어명·측정자·왼손/오른손**을 선택하고 **20회 수집 시작**을 누릅니다.
4. 5초 측정 + 3초 휴식을 20회 반복합니다. **일시 중지** 후 **계속 수집**할 수 있고, 중지 상태의 부분 수집도 전송할 수 있습니다.
5. **Python 서버로 전송**을 눌러 건수·주소를 확인한 후 전송합니다. 수집 중에는 전송할 수 없습니다.

잘못 측정했다면 **중지하고 버리기**를 누릅니다. 먼저 수집이 멈추며, **버리기**를 선택하면 이번 세션의 메모리 데이터와 이미 저장된 이번 CSV만 삭제합니다. **유지**를 선택하면 멈춘 상태에서 계속 수집할 수 있습니다. 이전 세션 CSV는 건드리지 않습니다. 전송을 시작한 세션은 이 버튼으로 폐기할 수 없습니다.

CSV는 이 폴더의 `sensor_data`에 저장합니다. 수집 중에는 메모리에 보관하고 **일시 중지·20회 종료·전송·새 수집·창 닫기** 때 저장합니다. 수집 중 매초 전체 CSV를 저장하던 작업을 없애고, 그래프는 0.25초 타이머에서 갱신해 BLE 수신 처리를 가볍게 했습니다. 비정상 종료 시 아직 저장하지 않은 메모리 데이터는 사라질 수 있습니다.

전송 전 CSV 저장 실패 시 전송하지 않습니다. 수집 시작 후 측정자·수어명·손은 고정됩니다. 바꾸려면 중지 후 **새 수집**을 누르세요. **새 수집**은 기존 CSV를 보존합니다.

전송은 백그라운드에서 처리하며 첫 HTTP 오류에서 멈춥니다. 서버가 이미 저장했지만 응답만 유실됐을 수도 있어 같은 세션의 전송을 다시 실행하지 않습니다. 미확인 건수와 CSV 경로를 확인하고 서버 기록과 대조하세요. 새 수집으로 같은 데이터를 재측정하면 별도 세션으로 저장됩니다.

서버는 기존 `post_sensor_batch`의 JSON 형식(`subject_id`, `session_id`, `seq`, `hand`, `trial_id`, `label`, `time_ms`, FSR 6개, IMU 6축)을 받습니다. 실제 오른손은 `right`, 왼손은 `left`로 전송합니다. 보드 재부팅 또는 3초 이상 BLE 수신 중단 시 수집을 멈춥니다.

로컬 HTTP 통합 테스트: 먼저 별도 터미널에서 `python3 tests/mock_sensor_server.py`를 실행합니다.  `XIAO_TEST_RECEIVER`를 임시 수신기 주소로 지정하고 `runtests('test_sensor_upload')`를 실행합니다. 임시 수신기는 `/sensor`에서 성공, `/fail`에서 seq=1 성공 및 seq=2에 HTTP 503을 반환해야 합니다. 실제 서버에는 시험 데이터를 보내지 마세요.

단일 모니터 자동 검증은 `runtests('test_sensor_single_monitor')`로 실행합니다. 모의 BLE와 임시 CSV 폴더를 사용하며 실제 서버에 전송하지 않습니다.
