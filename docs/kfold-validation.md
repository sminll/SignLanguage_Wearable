# FSR 시행 단위 K-fold 검증

`tools/evaluate_app_kfold.py`는 Git의 앱 수집 CSV를 읽어 여러 피험자의 시행을 합친 K-fold 평가를 재현한다. 기존 사람·기존 측정 세션의 다른 시행에 대한 탐색 평가이며, 새로운 사용자의 성능을 측정하는 LOSO와 구분한다. 원본 데이터나 운영 모델을 변경하거나 평가 모델을 배포하지 않는다.

## 실행

재현 실험은 Python 3.12, NumPy 2.3.5, scikit-learn 1.9.1에서 실행했다.

```bash
python3.12 -m venv .venv-kfold
source .venv-kfold/bin/activate
python -m pip install numpy==2.3.5 scikit-learn==1.9.1
git fetch origin training-data

python tools/evaluate_app_kfold.py \
  --ref 4d4d24a4d672c78d934bf120a59a193c2340637e \
  --out data/knn_results/kfold_20261116 \
  --audit-groups
```

항상 새 출력 디렉터리를 지정한다. 기존 디렉터리는 덮어쓰지 않는다. 다른 데이터 시점은 `--ref origin/training-data`로 지정할 수 있지만 결과도 달라질 수 있다. 커밋 SHA와 입력 파일별 SHA-256은 `manifest.json`에 기록한다.

빠른 기능 점검은 `--max-folds 2 --seeds 42`를 추가하면 된다. 반복 1회의 표준편차 0은 안정성의 증거가 아니다.

## 데이터와 특징

- `source=REAL`이고, `record_kind`가 있으면 `training`인 CSV 행을 사용한다.
- `subject-N`과 `subjectN`을 같은 숫자 피험자 ID로 묶는다. 이름은 모델 입력에 포함하지 않는다.
- 피험자·세션·시행 ID로 양손을 짝짓는다. 같은 시행의 정답 라벨이 충돌하면 중단한다.
- 각 손의 FSR1~6에 유효 숫자가 채널당 8개 이상 있는 시행만 사용한다. 정상적인 0은 포함한다.
- FSR별 평균·표준편차(`ddof=0`)·최소·최대를 계산한다. 한 손 24차원, 양손 48차원이다. IMU는 사용하지 않는다.
- 요청에 따라 테스트 라벨 3개는 기본 제외한다. `--exclude-label`로 추가 제외할 수 있다. 다른 유사 동작명은 임의로 합치지 않는다.

이 도구의 기본 범위는 **모든 기록 코호트를 포함하는 탐색 비교**다. 착용 위치·세션 품질이 검증된 운영 학습 코호트라는 뜻이 아니다. 운영 제외 목록을 적용하려면 `--exclusion-manifest data/training_exclusions.json`을 명시한다. 지정된 파일이 해당 커밋에 없거나 해시가 다르면 중단한다. 빈 목록은 제외 파일 0개로 기록하며, 과거 제외 이력은 자동 적용하지 않는다.

## 평가 순서

1. 전체 시행을 동작 비율을 유지해 개발 80%·최종 시험 20%로 분리한다. 기본 분할 Seed는 `20261116`이다.
2. 개발 세트 안에서 `StratifiedKFold`의 Fold 수를 2부터 비교한다. 기본 상한 20과 개발 내 최소 동작 시행 수 중 작은 값까지 사용한다.
3. 매 Fold마다 **학습 부분에서만** `StandardScaler`를 적합한다. `z=(x-학습 평균)/학습 표준편차`이며, 최댓값으로 나누거나 전체 데이터를 미리 정규화하지 않는다.
4. KNN 이웃 수 3, 균등 투표, 유클리드 거리를 고정한다. `--neighbors`는 명시적으로 바꿀 수 있지만 이 도구가 이웃 수를 탐색하지는 않는다. Fold 수 K와 KNN의 K는 서로 다르다.
5. Seed 42~46으로 각 조건을 5번 반복한다. 매 반복에서 각 개발 시행은 검증용으로 정확히 한 번 사용된다. 오른손·왼손·양손은 같은 분할을 사용한다.
6. 평균 OOF 정답률, Macro F1, 작은 Fold 수 순으로 조건을 선택해 `selection.json`에 먼저 저장한다. 이후 개발 전체로 다시 학습하고 보존한 시험 세트를 평가한다.

Fold 수는 평가 설계이지 모델 파라미터가 아니다. Fold 10보다 11의 점수가 높았다고 해서 최종 모델이 개선된 것은 아니다. 최종 개발 데이터와 KNN 설정이 같으면 같은 모델을 학습한다. 최종 시험 점수로 Fold 수나 입력을 다시 고르지 않는다.

`--audit-groups`는 양손 48개 특징으로 **측정 세션 전체 제외**와 **피험자 전체 제외**를 추가 계산한다. 이 감사 결과는 전체 원본 시행에 대한 OOF 평가이며 고정된 20% 시험 세트와 표본 수가 다르다. 세션을 제외하면 동일인·동일동작의 학습 자료까지 사라질 수 있어, 재착용 효과만 분리한 인과 실험은 아니다.

## 확인된 재현 결과

위의 고정 커밋에서 10명·24개 라벨·2,269개 시행이 포함됐다. 개발 1,815개, 시험 454개이며 최소 개발 클래스가 11개여서 Fold 2~11을 각 5회 비교했다.

| 입력 | 검증 정답률 최고 Fold | 평균 검증 정답률 | 최종 시험 정답 | 최종 정답률 | 균형 정확도 |
|---|---:|---:|---:|---:|---:|
| 오른손 | 9 | 66.98% | 297/454 | 65.42% | 65.93% |
| 왼손 | 10 | 57.40% | 272/454 | 59.91% | 65.53% |
| 양손 | 11 | 81.93% | 386/454 | 85.02% | 88.63% |

양손 10-fold는 검증 정답률 81.87%, Macro F1 83.75%였고 11-fold는 81.93%, 83.73%였다. 정답률 차이 0.055%p를 의미 있는 모델 개선으로 해석하지 않는다.

같은 Fold·Seed에서 정규화를 생략한 양손 비교 정답률은 82.98%였고 표준화 후에는 81.93%였다. 표준화가 항상 성능을 높이는 것은 아니다. 이 사후 기준선으로 선택을 다시 바꾸지는 않았다.

양손 추가 감사는 측정 세션 전체 제외 486/2,269=21.42%, 피험자 전체 제외 523/2,269=23.05%였다. 고정 시험 454개는 전부 학습과 동일한 사람·세션을 공유했다. 따라서 **85.02%를 새 세션·새 사용자 성능으로 보고하면 안 된다.** 기존 Git 문서의 IMU·3개 동작 등 다른 조건의 LOSO 수치와도 직접 혼용하지 않는다.

## 출력 읽는 법

| 파일 | 내용 |
|---|---|
| `manifest.json`, `selection.json` | 입력 커밋/해시, 설정, 라벨 목록, 선택 규칙, 평가 범위와 한계 |
| `trial_features.csv`, `split.csv` | 시행별 원시 통계 특징과 개발/시험 분할 |
| `cv_summary.csv`, `cv_runs.csv`, `cv_folds.csv` | Fold별 반복 평균, 반복별 결과, 개별 폴드 결과 |
| `cv_predictions.csv` | 선택된 Fold 수의 첫 Seed OOF 예측. 전체 5회 평균과 구분 |
| `test_summary.csv`, `test_predictions.csv` | 분리된 내부 시험 정답률·Macro F1·균형 정확도와 시행별 예측 |
| `normalization.csv` | 최종 개발 세트에서 적합한 특징별 평균·분산·표준편차·실제 나눗값 |
| `normalized_features.csv` | 최종 개발 기준으로 변환한 조회용 값. CV 폴드별 기준이 아니므로 이것을 미리 적용해 CV를 돌리면 안 됨 |
| `normalization_comparison.csv` | 사전 선택한 Fold의 정규화 전후 탐색 비교 |
| `group_audits.csv`, `group_folds.csv` | 선택 옵션의 세션/사람 제외 결과, 미학습 라벨 및 동일인·동일동작 학습 범위 변화 |

정답률은 맞힌 시행 수/시험 시행 수다. 균형 정확도는 실제 등장한 동작별 재현율의 평균이며, 예측 확신도나 실사용 신뢰도 보증이 아니다. 반복/폴드 표준편차도 신뢰구간이 아니다. 이 데이터는 이전 분석에도 등장했으므로 내부 시험을 신규 외부 검증이라고 부르지 않는다.

## 테스트

```bash
python -m unittest discover -s tests -p 'test_app_kfold.py' -v
```

합성 Git 저장소에서 원본 불변, ID 정규화와 양손 짝, 라벨 충돌, 유효 표본 수, 기존 출력 보호, 희소 클래스 Fold 상한, 학습/시험 시행 분리, 학습 세트 기준 표준화 및 점수 재구성을 확인한다. 실제 데이터 재현은 위의 고정 커밋 실행 결과와 별도로 확인한다.

참고: [StandardScaler](https://scikit-learn.org/stable/modules/generated/sklearn.preprocessing.StandardScaler.html), [그룹을 고려한 교차검증](https://scikit-learn.org/stable/modules/cross_validation.html), [데이터 누출 방지](https://scikit-learn.org/stable/common_pitfalls.html).
