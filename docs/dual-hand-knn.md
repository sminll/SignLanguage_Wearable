# XIAO 2개 수집과 양손 통합 KNN

구현 브랜치: `feature/dual-hand-knn`. 2026-11-11 최신 `main` 기준으로 통합·재검증했습니다.

이 문서는 MATLAB 양손 수집기의 시간·수어 유형 메타데이터와 전용 비교 도구 안내입니다.
기존 앱 데이터 분석 코드나 현재 저장된 IMU KNN 후보 모델을 교체하거나 재학습하지 않습니다.
앱 CSV의 UUID 회차·여러 수어 세션은 기존 `tools/` 분석 도구를 사용하세요.
펌웨어, BLE UUID·패킷 디코더·연결/알림 구독 방식은 유지합니다.
종료 정리 객체는 함수 작업 공간이 살아 있을 때 명시적으로 해제하도록 보완했습니다.
5초 측정 + 3초 휴식 × 20회도 유지합니다. 이 양손 수집기는 기존과 같이 5초 동작 구간을 저장합니다.

## 적용 순서

1. 서버 PC와 측정 PC의 코드를 모두 이 변경이 반영된 `main` 버전으로 맞춥니다.
2. 기존 전송이 끝난 뒤 서버를 재시작합니다.

```powershell
python receive_sensor.py --host 100.92.15.45
```

3. `/health` 응답에 `schema_versions: [2, 3]`이 있는지 확인합니다.
   이미 정상 응답하면 서버를 중복 실행하지 마세요. 수신기 교체 시 터미널뿐 아니라
   실제 5000번 포트의 프로세스가 종료됐는지 확인해야 합니다.
4. MATLAB Current Folder를 `MATLAB_노트북용_수정본`으로 지정하고 두 보드 주소로 실행합니다.

```matlab
blelist
xiao_ble_dual_monitor("LEFT_BOARD_ADDRESS", "RIGHT_BOARD_ADDRESS")
```

5. Subject·수어명을 선택하고 수어 유형을 선택합니다.

| UI 선택 | 기록 값 | 측정 방식 |
|---|---|---|
| 왼손만 | left_only | 왼손 동작, 오른손 자연스럽게 내림 |
| 오른손만 | right_only | 오른손 동작, 왼손 자연스럽게 내림 |
| 양손 | both | 양손 동작 |

**선택에 관계없이 두 손 모두 CSV 저장·서버 전송합니다.** 유형은 수집을 시작하면 잠깁니다.
다른 유형은 새 수집으로 시작합니다. 기존 정보 수정은 Subject·수어명에 적용됩니다.
좌우 보드 주소를 바꿔 입력하지 말고 FSR을 직접 눌러 손 대응부터 확인하세요.

6. 처음에는 짧게 수집·일시 중지해 두 CSV를 확인하고 시험 전송합니다.
   본 수집은 양쪽 값이 들어오는 것을 확인한 뒤 시작합니다.

현재 물리 보드 2개의 실물 동시 측정은 이 변경의 자동 테스트 범위 밖입니다.

## 데이터 형식과 기존 데이터 보존

MATLAB 원본은 손별 파일이며, 두 파일은 같은 `subject_id/session_id/source(trial_id)`를 공유합니다.
기존 19열에 아래 3개가 추가돼 새 양손 CSV는 22열입니다.

- `gesture_type`: 왼손만/오른손만/양손
- `host_elapsed_ms`: 두 보드가 공유하는 PC 수집 시계. 일시 중지 시간을 제외한 세션 진행 밀리초.
- `trial_elapsed_ms`: 해당 5초 측정 구간 안의 수신 밀리초

`time_ms`는 각 보드의 독립 부팅 시계로 그대로 보존하며 좌우 절댓값을 비교하지 않습니다.
공통 시간은 PC에서 패킷을 수신·처리한 시각이므로 하드웨어 동기화나 BLE 지연 보정값이 아닙니다.

서버 저장:

| 입력 | 저장 파일 | 형식 |
|---|---|---|
| 기존 payload | data/sensor_dataset_v2.csv | 기존 21열 유지 |
| 시간·유형 포함 payload | data/sensor_dataset_v3.csv | 24열, 별도 파일 |

v3는 첫 실제 샘플이 도착하면 생성합니다. 기존 v2 CSV나 과거 모델을 마이그레이션·덮어쓰기하지 않습니다.
같은 샘플을 v2와 v3로 중복 저장하지 않으며 형식 간 동일 키 충돌은 409로 차단합니다.
동일 session/hand/seq 재전송은 중복을 건너뛰되, 센서값이나 시간·유형이 다르면 충돌로 중단합니다.
한 세션의 측정자·수어·유형도 일관돼야 합니다.
메타데이터가 일부만 들어오면 구형 데이터로 간주하지 않고 오류를 반환합니다.

새 MATLAB 전송기는 서버 v3 지원을 먼저 확인합니다. 구버전 서버라면 보내지 않고 원본 CSV를 보존합니다.
전송 후 Python으로 재전송할 때도 새 열을 유지합니다.

```powershell
python resend_sensor_v2.py --endpoint http://100.92.15.45:5000/sensor
```

파일 선택은 손별로 합니다. v2와 v3 원본을 임의로 합치거나 v3 열을 지우지 마세요.

## 양손 회차 결합과 품질 검사

```powershell
python train_dual_knn.py --date 2026-11-02
```

기본 입력은 v3이며, 결과는 매번 새 `data/knn_results/paired_.../`에 생성합니다.
`--input`과 `--output`으로 별도 CSV·새 결과 폴더를 지정할 수 있습니다.

- 한 샘플 = 같은 참가자·세션·회차의 좌우 데이터. 같은 회차가 다른 label/유형이면 제외.
- 공통 회차 시간으로 좌우를 150ms 이내에서 가까운 순서대로 일대일 대응. 오른손 샘플을 재사용하지 않음.
- 각 손 최소 8샘플, 시간 범위 최소 3초, 시작 1초 이내·종료 4초 이후 필요.
- 수신 사이 큰 공백이 500ms를 넘거나 대응 샘플이 많은 쪽 손의 70% 미만이면 제외.
- 보드 재시작·장치 시간 구간과 PC 시간 구간의 큰 불일치도 제외.
- 결합된 샘플의 양쪽 시간 범위도 3초 이상이어야 함.
- 손 누락은 0으로 채우지 않고 제외. 센서 전체 결측은 제외, 부분 IMU 결측은 학습 fold 안에서만 중앙값 보완.
- `pair_quality.csv`에 회차별 승인/제외 이유, 샘플 수, 대응 비율, 시간 차이를 기록.

허용치는 초기 정책이며 실물 측정으로 검증해야 합니다. CLI로 조절 가능:
`--tolerance-ms`, `--max-gap-ms`, `--min-span-ms`, `--min-match-fraction`.
시험 점수를 본 뒤 정책을 조정했다면 같은 시험 세트를 독립 검증 점수로 재보고하지 마세요.
일정하게 지연된 패킷 등은 수신 시간만으로 완전히 감지할 수 없습니다.

## 기존 한 손 vs 양손, 반대 손 활용 비교

양쪽을 대응시킨 뒤 각 손에 기존과 같은 48개 특징(FSR+IMU 각 평균/표준편차/최솟값/최댓값)을 계산합니다.
양손은 96개입니다. 전처리는 각 학습 fold 안에서만 fit합니다.

`comparisons.csv`는 두 집단을 구분합니다.

| 집단 | 비교 모델 |
|---|---|
| all_paired | 왼손 48개 / 오른손 48개 / 양손 96개 |
| one_hand_signs | 사용하는 손 48개 / 움직이지 않는 손 48개 / 양손 96개 |

각 집단 안에서는 **동일한 승인 회차와 동일한 fold**를 사용합니다.
`*_folds.csv`와 `*_predictions.csv`로 대상이 같은지 확인할 수 있습니다.
두 손을 따로 학습/평가 집합에 나누지 않습니다.
같은 집단의 both와 active 점수 차이가 반대 손을 추가했을 때의 비교입니다.
서로 대상이 다른 집단의 점수나 과거 93.3%와 단순 비교하지 마세요.

기본 `--split subject`는 참가자를 통째로 제외하며, 참가자별 수어 구성이 부족해 평가가 불가능하면 점수를 만들지 않습니다.
한 사람뿐일 때 초기 동작 확인은 `--split trial`로 명시적으로 실행할 수 있지만 신규 참가자 성능이 아닙니다.
평가할 수 없는 경우도 특징·품질 보고서는 저장합니다. 최소 2수어가 없으면 분류 모델을 만들지 않습니다.

수어 유형은 분류 입력에 직접 넣지 않습니다. 단 active/passive 비교는 실제 사용하는 손을
사전에 안다는 가정의 비교이므로, 어떤 손을 쓰는지도 모르는 실시간 인식 성능으로 주장할 수 없습니다.
기본 both 모델은 그런 입력 선택 없이 좌우 고정 순서로 사용합니다.
모델은 비교별 새 파일로 저장하며, 저장된 전체 데이터 학습 모델과 CV 평가에 사용한 fold 모델을 구분합니다.
어느 모델도 서버·MATLAB에 자동 배포하지 않습니다.

## 기존 한 손 분석

기존 명령은 계속 사용 가능합니다.

```powershell
python train_sign_knn.py --date 2026-11-01 --board XIAO
python train_sign_knn.py --input data/sensor_dataset_v3.csv --hand left --output data/knn_results/새로운_왼손_실험
```

첫 명령은 과거 v2 및 로컬 장치 매핑을 사용합니다. 두 번째는 v3에서 한 손을 따로 분석합니다.
엄밀한 양손 비교에는 같은 회차를 쓰는 `train_dual_knn.py` 결과를 사용하세요.

공통 시간이 없는 과거 양손 v2는 기본적으로 timing_unknown으로 제외합니다.
`--allow-legacy-timing`을 명시하면 손별 요약을 결합하는 탐색 분석은 가능하지만 동기화가 검증된 결과는 아닙니다.
수어 유형도 unknown이므로 active/passive 비교에는 사용하지 않습니다.

- MATLAB: payload/CSV/수집 주기/한 손 회귀/양손 UI/HTTP 통합 총 43개 통과 (R2025b).
- 모의 BLE로 왼손만·오른손만·양손의 양쪽 CSV 저장·유형 고정 확인.
- 독립 장치 시계·작은 누락·큰 공백·회차 불일치·보드 재시작·중복·잘못된 메타데이터 확인.
- 임시 수신기로 v3 전달 및 구버전 서버에서 전송 차단, 중복/충돌 처리 확인.

실제 반대 손의 정보가 정확도에 도움이 되는지는 새 형식으로 여러 사람·여러 수어를 수집한 뒤 확인해야 합니다.
