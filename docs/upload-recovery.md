# HTTP 500 전송 복구

서버가 센서 데이터를 저장한 뒤 HTTP 500을 반환하면 MATLAB은 응답을 확인하지 못해 전송을 중단한다. 현장에서 1,388행 중 99행 확인 후 중단되었으며, 동일 session_id/hand/seq로 재전송했을 때 서버가 HTTP 200 / status=duplicate를 반환하는 것을 확인했다. 이후 모든 행의 saved/duplicate 응답을 확인해 복구했다.

MATLAB post_sensor_batch의 선택적 세 번째 인수가 true일 때만 HTTP 500을 한 번 재확인한다. 단일 보드 모니터는 receive_sensor.py의 (session_id, hand, seq) 중복 방지 계약을 전제로 이를 사용한다. 재확인 시 payload와 키는 그대로 유지한다. 타임아웃, 409 충돌, 기타 오류 및 두 번째 500은 미확인으로 중단한다. 다른 호출자는 기본값 false로 기존 동작을 유지한다. 중복 방지를 지원하지 않는 서버에는 이 옵션을 사용하지 않는다.

관측상 100행마다 첫 요청 500 / 동일 요청 재확인 성공이 반복됐다. 로컬 서버 코드는 저장 및 중복 등록 뒤 100행마다 stdout 로그를 출력하므로 이 출력 지점이 원인 후보지만, 원격 traceback을 확인하지 않아 정확한 예외는 확정하지 않았다. 서버 자체 원인 점검은 별도로 필요하며 이 수정은 클라이언트의 제한적 복구다.

검증은 localhost 모의 서버에서 저장 후 500, 반복 500, 기본 재시도 비활성, 성공 전송, 부분 실패 중단, backgroundPool 전송을 확인한다. 테스트 서버는 실측 데이터를 사용하지 않는다.
