# 수신 현황과 모델 정확도 표시

`편두통 동작 데이터 수신 점검` 채팅의 최신 평가 설명과 저장된 실험 결과를 대조했다. 채팅 제목의 편두통 동작(갑자기·머리·아프다) 초기 모델과, 이후 앱 데이터(삼키다·상처·교통사고) 모델은 서로 다른 실험이다.

## 지금 표시할 수 있는 결과

| 결과 | 분자/분모 | 알림에서의 해석 |
|---|---|---|
| 559회차 사람별 LOSO | 413/559, 73.88% | 설정 선택 후 내부 교차검증 참고 결과 |
| 이전 319회차 개발 모델의 신규 4명 평가 | 148/240, 61.67% | 해당 이전 모델의 외부 평가 이력 |
| 현재 559회차 저장 후보의 새 사람 평가 | 미실시 | 미확인 |
| 이미 학습한 559회차 재예측 | 555/559, 99.28% | 훈련 데이터 점수이며 운영 정확도로 표시하지 않음 |

이번 알림에서는 삼키다·상처·교통사고 수집 건에 **이전 내부 교차검증 73.88%**를 참고로 표시한다. 항상 **이번 업로드 정확도: 미평가**라는 문장을 함께 표시한다. 지원 수어가 아닌 테스트/다른 동작에는 해당 점수를 표시하지 않는다. 수신 기본 검사 통과율을 분류 정확도로 바꾸어 표시하지 않는다.

수치와 모델 해시는 `docs/data-notification-settings.json`에 검토된 자료로 저장한다. 이 파일은 새 업로드 때 자동으로 성능을 재계산하는 기능이 아니다. 결과를 갱신할 때 모델, 평가 대상, 평가 방식, 분자/분모와 기록 링크를 함께 검토한다.

## 새 업로드의 정답률을 자동 표시하는 구현 가능성

**기술적으로 가능하지만, 업로드 검사만으로는 계산할 수 없다.** 아래 요소가 추가로 필요하다.

1. **평가할 모델 고정**: 모델 파일·SHA-256·학습 참가자/회차 목록·센서와 특징 순서를 명시한다. 파일명이나 날짜만으로 최신 모델을 자동 선택하지 않는다.
2. **실행 환경 준비**: 현재 후보는 로컬 `data/knn_results/`에 있고 GitHub Actions에는 올라가 있지 않다. 신뢰할 수 있는 모델 아티팩트 보관소와 현재 저장 환경에 맞는 의존성 버전이 필요하다.
3. **새 데이터 적합성 확인**: 후보가 지원하는 세 수어, 양손 IMU, 회차 단위 특징 추출이 맞는지 확인한다. 왼손만 있는 오늘의 디스코드 테스트는 이 양손 후보의 평가 대상이 아니다.
4. **학습 자료와 평가 자료 구분**: 동일 데이터·사람이 학습에 포함됐는지 확인하고, 새 사람 평가/기존 사람의 새 세션/내부 검증을 서로 다른 이름으로 기록한다.
5. **예측 결과 저장**: 수어별 정답/평가 회차, 대상 파일 해시, 모델 해시, 지원하지 않아 제외한 회차와 이유를 기록한다. 평가 실패를 0%로 표시하지 않는다.

이 조건을 갖추면 기존 수집 현황 메시지에 `삼키다 18/20 정답 (90%) · 새 사람 평가 · 모델 SHA…` 같은 결과를 추가하고 같은 메시지를 갱신할 수 있다. 평가 전에는 숫자를 추정하지 않는다.

기존 `tools/evaluate_frozen_app_model.py`는 120회차 특정 모델과 지정 참가자에 고정된 검증 도구다. 559회차 후보에 그대로 연결할 수 없다. 자동 평가를 추가한다면 후보의 48개 IMU 특징·학습 목록을 사용하는 별도 실행 경로가 필요하다. 이번 작업에서는 모델을 학습·교체·배포하지 않는다.
